# D39 (tail expressions, discarded values): the W4-03 arms and their census

Base: aether 7f58a33 (language 2026-10-07-1). Sets as in
`w7-24a_type_oracle.md` (tests 245, examples 70, corpus 748, archive 413
cleaned programs; 18 nondeterministic programs compared on AST and diagnostics
only).

## The arms

`AETHER_EXPERIMENT=tail=<rule>` (parser-level, src/aether/ast_parser.c):

- **`reject`**, D39 (a), W4-03 parts 1 and 2:
  - A value-only expression statement (a name, literal, operator expression,
    index, field read, array literal, if-expression) is a coded error. Inside
    a non-Void function the message is FLOW-001 "value computed and discarded;
    Aether has no implicit return.", with the hint "write `ret <expr>;` (a
    branch value: `ret if c { a } else { b };`)". Elsewhere it is SYN-001
    "this expression has no effect."
  - At the three optional-`;` sites (expression statement, `let`, `ret`), a
    token that starts on the line of the token before it, with no `;` between
    them, is SYN-001 "missing operator or `=` between `price` and `qty`?". A
    statement keyword on that line (`fn`, `let`, `if`, ...) is exempt, and so
    is a lone word in front of one: that is a missing `;` or a foreign
    modifier (`pure fn`), which keeps its current diagnostic.
  - Calls, assignments and the lowered append/concat compounds are untouched.
    W4-03 part 3 (an assignment used as a condition) is not in this arm.
- **`ret`**, D39 (b): in a non-Void function the final bare value of the body,
  or of each branch of a final `if`/`else` (recursively), becomes
  `ret <value>;`. A final call to a user function with a non-Void return
  counts too. It is not applied under `@post` or a tuple return, whose `ret`
  lowering is more than a RETURN node.

| arm | programs that ran and now fail | stdout changes | first code changes on already-failing programs | message changes, same code |
|---|---|---|---|---|
| `reject` | **0** | 0 | 0 | 8 (3 `_fail` fixtures, 5 archive programs that do not compile today) |
| `ret` | 0 | 0 | 0 | 0, plus 1 `_fail` fixture that now compiles and runs (`function_missing_value_return_fail`, whose `n * 2` tail becomes its return) |

Graded first attempts (the 304 in the umbrella's tracked results, recompiled

**No first attempt changes class under either arm.**

So W4-03's verification bar, 0 bare-statement hits in tests, examples, corpus
and archive, holds for the `reject` arm: it rejects nothing that compiles
today. Neither arm costs anything on the programs we have. They differ only on
programs that are wrong today.

## Deletion sweep: what `reject` buys

The 182 deterministic seeds (pass fixtures and examples that run with rc 0 and
use no randomness, clock, environment, network or `par`) give 1,460
single-token deletions of a binary operator or `=`. Each mutant is run under
both arms and classified against the seed's stdout:

| deletion | arm | mutants | rc 0, same stdout | rc 0, **wrong stdout** | coded | uncoded | hang |
|---|---|---|---|---|---|---|---|
| `=` | shipped | 925 | 169 | **400 (43.2%)** | 218 | 124 | 14 |
| `=` | `tail=reject` | 925 | 22 | **0 (0.0%)** | 900 | 3 | 0 |
| operator | shipped | 535 | 74 | **232 (43.4%)** | 169 | 46 | 14 |
| operator | `tail=reject` | 535 | 48 | **7 (1.3%), all a deleted unary minus** | 449 | 31 | 0 |

The rc-0 rate, wrong or same, falls from 61.5% to 2.4% for `=` and from 57.2%
to 10.3% for operators. W4-03 targets below 5% silent acceptance. Every one of
the 7 remaining wrong answers deletes a *unary* minus (`classify(-1)`,
`step -4`, `-1..2`), which the sweep's tokeniser counts as an operator.
Deleting a sign leaves a valid program that means something else, and no
parse rule can catch that. Deleting a binary operator, under `reject`, never
produced a wrong answer with rc 0 here. The remaining rc-0 operator deletions
print the same output (an operand of 1, a sign-neutral value). The 28 hangs
under the shipped compiler (`i = i 1` in a loop) all become coded errors.

## What the evidence says for D39 (not a decision)

D39's pre-registered rollback for (a) is "any unwaived pass→fail, or FLOW-001
becoming the top new first diagnostic with B_L1 first attempt down 3 pts". The
first leg is measured here: 0 pass→fail over 1,459 run programs, and 0 class
changes over 304 graded first attempts. The second leg needs B_L1 on the rig.
Arm (b) changes nothing that runs today and legalises exactly one fixture
written to be rejected. Across these populations, neither arm moves a
first attempt, so D39 still waits on B0/B1. The deletion sweep is the one
measured benefit, and it is (a)'s: wrong-answer-with-rc-0 falls from 43% to
0% of binary-operator and `=` deletions.

## Commands

```sh
tools/aether_experiment_census.py --timeout 60 \
  --arm base=<7f58a33>/aether: --arm head=build/aether: \
  --arm reject=build/aether:tail=reject --arm ret=build/aether:tail=ret \
  <the four source sets> --nondeterministic <18 keys> --json tail.json
tools/aether_first_attempt_histogram.py --bench-root <umbrella> --recompile \
  --aether-bin build/aether --experiment tail=reject '<umbrella>/Tests/aether_doc_bench/results/**/*.json'
```

The deletion sweep is a scratch script, not in the tree. It deletes each
binary-operator and `=` token once per seed (a regex tokeniser that skips
strings and comments) and runs each mutant in a fresh directory under
`AETHER_EXPERIMENT` unset and `tail=reject`. W4-03 proper vendors the review's
`bare_stmt_scan.py` and `deletion_sweep.py` into `tools/`.
