# D8 (array parameters): V-strict census and by-ref arm, W8-09

Base: aether 7f58a33 (language 2026-10-07-1). The program sets are as in
`w7-24a_type_oracle.md`: tests 245, examples 70, corpus 748, archive 413
cleaned programs. 18 nondeterministic programs are excluded from run
comparison. All numbers come from the lane's final binary. The first run, on
this commit's binary over the 629 raw archive files, found the same programs
plus duplicates of two of them.

## The arms

`AETHER_EXPERIMENT=arrays=<rule>` (src/aether/experiment.c):

- **`vstrict`** (warn mode, census only): every write to an array parameter
  in any function that does not return that parameter (alone, in a tuple slot,
  or through `@post`'s `result`) gets an ARR-001 *warning* saying V-strict
  would reject it. A write is a direct index store, a nested store
  (`g[r][c] = v`, or a whole row of a rank≥2 parameter), a resize (`setlength`,
  an append), or a reassignment. The lowering's own un-alias copies
  (`setlength(p, length(p))`) are not writes. Stores into fields of record
  elements (`ps[i].x = v`) reach the caller anyway and are not counted. The
  direct-index-in-a-Void-function case is already the shipped ARR-001
  warning, so `vstrict` logs it and adds no second warning.
- **`ref`**: array parameters are passed by reference (`by_ref`, on the
  definition and its forward prototype) with no prologue copy. Three
  front-end shims make the existing VM path usable:
  1. An rvalue argument moves into a temporary declared just before its
     statement. A call in a `while` condition is logged "unhoistable".
  2. Before a call to a parameter the callee resizes, the caller's storage is
     normalised with `setlength(v, length(v))`. The VM cannot `setlength` a
     literal-built (static) array through a reference ("SetLength expects a
     string or dynamic array target").
  3. A whole-value read of a by-ref parameter (`let c = xs;`, `ret xs;`, a
     tuple slot) becomes an element-wise copy. The VM hands back the
     reference itself, and the un-alias step after the copy fails.
  `let b = a` and assignments still copy.
- `AETHER_EXPERIMENT_LOG` logs every write (`arr` rows: param, write kind,
  fn kind, `returned`/`lost`) and every `ref` shim (`arr-ref` rows).

## What the evidence says for D8 (not a decision)

D8's rule picks by-ref only if its mutation-trap first-attempt pass is ≥
V-strict + 5 points, its silent-wrong share is no higher, and its replay
pass→fail is ≤ 1% of the corpus. The replay leg is measured: 0.27% (1
semantic change and 1 VM defect in 734 goldens), inside the bound. The
census cannot settle the other two legs. In these sets V-strict and the
shipped ARR-001 flag the same 5 programs. They split 2 bugs, 2 correct
scratch uses and 1 fixture, so V-strict's error would cost exactly the
scratch programs. The mutation-trap probe (Lomuto, heapify, DFS visited,
union-find, sieve, DP fill, scratch median; 4 models × 5) needs the rig and is
not run here. The arms are ready for it: compile the generations under
`arrays=vstrict` (count the warnings as V-strict's rejections) and
`arrays=ref`.

## Deviations

- The plan's arm drops the prologue copy, and it does here. A real by-ref
  release cannot ship shims 2 and 3 as they stand: shim 2 adds a caller-side
  copy before a call that resizes, and shim 3 copies whole-value reads (the
  VM gives back the reference). Both work around pscal-core's VAR-array
  handling, along with the method-call pass-through crash. A by-ref outcome
  for D8 needs those fixed in pscal-core first.
- Calls into module functions are not hoisted (modules load during rea's
  semantic pass, after the hoist runs). None occurred in these sets.
