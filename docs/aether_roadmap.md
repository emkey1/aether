## Research plan for models

**The seed check.** Each two-arm, two-seed study defines it from its own runs: every run of one arm ahead of every run of the other, and the arm difference beyond either end of the 95% interval of that study's seed-only contrast, which puts one run of each arm on each side. It can only weaken a reading. It is a one-draw guard, not an estimate of seed variance, and it has no form for three or more seeds or more than two arms: those designs wait for Q15's rule.

**Standing rules.** Each README names one grader hash for all arms; a dataset or pool built on an older language is replayed on that grader first. First attempt decides, with a non-deciding repair column required before a model is proposed for publishing. A repair reading uses one stored set of failing programs, fixed before the arms are trained, one round, paired by program, with a resample arm: the recorded repair figures are unpaired, and 15 of 134 and 21 of 163 "repairs" were a second first attempt (`training/distill/fv3-20261105/README.md:82`).

**R3. Then one recipe at eight seeds fixed in advance, two from R2, on the 2,802 tasks R2's base runs are scored on, a use recorded in B5's ledger; one R2 base run is re-scored in the R3 session to measure the session gap; one server version. *Measure:* per-task discordance between seeds, and between two passes of one set of weights. *Rule:* the floor is the smallest seed count whose arm-difference error, from the upper bound of the between-seed variance, is under Q25's margin; the README says beforehand what eight seeds can show. It covers the 12B only as an assumption. *Cost:* Q25; six S runs; eight passes (six new, one R2 base run re-scored, one repeat pass of one set of weights). *Needs:* R2.

**R4. Two epochs or three on the 4B?** *Hypothesis:* none; the MoE's +0.29 [-0.79, +1.36] (`training/distill/fep-20261118/README.md:59`) had one run per arm, and its "two epochs" was a cost decision. *Arms:* seeds a side are the larger of three and R3's floor (at Q25's margin); all eight R3 runs are the three-epoch arm. *Measure:* two minus three epochs on 2,802 fresh tasks, both arms answered in one session on one server version (the three-epoch runs re-answered), since otherwise session is aligned with the arm, as in Q2. *Rule:* two epochs only if the lower bound is above minus M, M set by a formula written in R3's README before R3 is read (a multiple of the between-seed error at the floor); otherwise "not resolved, recipe unchanged". The field is per model, not per family. *Seed noise:* seeds as the unit; design open until Q15 writes that rule. A 12B mid-schedule adapter is reported only: in fep such a cut sat 1.14 to 1.43 points under both finished schedules (`:64`). *Cost:* three S runs at least, and a pass per run of both arms. *Needs:* R3, Q15.

**R5. Learning rate and rank on the 4B.** *Hypothesis:* once learning rate is tuned, LoRA variants land within 1 to 2% of each other (reported, arXiv 2602.04998). Every from-scratch run used rank 32, alpha 64 and 1e-4. *Design, fixed before any run:* screen three other rates, then three ranks, at one seed on the 1,026 tasks; the screen drops only arms below base by more than R3's seed gap, and the rest advance; selection at three seeds on the 1,776; confirmation at R3's floor of fresh seeds on a part of the new pool, by one contrast, best minus base. The README states the smallest difference R3's floor resolves; the confirmation runs only if selection's best arm leads base by at least that. No claim from the screen. *Seed noise:* seeds as the unit under Q15's rule. A confirmed arm changes the 4B default and earns one 12B check. *Cost:* L. *Needs:* R2 to R4, B5, Q15.

**R6. How much data is enough, on the 4B?** *Hypothesis:* unknown; an outside 8B fine-tune reached 83.2% with 2,316 examples against 84.2% with all 4,633, a pass rate on a benchmark that scores execution, not correct output (reported, arXiv 2609.23367; 4-bit QLoRA; no seed variance). *Arms:* all, half and quarter of the frozen dataset (2,278 instruction and 87 repair records, `training/training_runs/qwen36-35b-a3b-v2/README.md:6`), with a step-matched control at half. A leave-one-type-out arm runs only for a type holding a stated share of records, beside a same-size random removal, judged on a script-defined sub-pool of tasks that exercise the type. *Rule:* the contrasts are counted beforehand; each is read alone. *Seed noise:* every deciding arm carries R3's floor; one-seed arms only screen. *Cost:* decisions on sizes and the share; L. *Needs:* R1, R3, Q15.

**R7. What does the next dataset change?** Conditional on R1, which read "not shown" on 2026-11-26: what remains is Q24 and the repair arm below. On "not shown", Q24's default is recorded and no selection arm runs. On "not separable", filtering is unchanged and the only open decision is more seeds. On "passed-task data helps more": stop filtering, as registered. On "targeting helps": the existing 298 targeted pairs against 298 coverage-chosen pairs, on the 12B. Design open: how many 12B seeds resolve a difference smaller than the +3.70 total gain; R3 measures the 4B. Outside, difficulty-based selection often fails to beat random and coverage-based selection matches or beats it (reported, arXiv 2611.07323). The repair arm stands alone: baseline against baseline plus triples from the distillation solvers' own fixed attempts, never a fine-tune's (Q26), two seeds, read on the fixed failing set with its own seed check. *Follows:* a new `training/PLAN-next-dataset.md`. *Cost:* Q24, Q26; L if run. *Needs:* R1, B5.

### Inference

These train nothing; their noise is sampling and serving, which B3's two A/A kinds measure.

**I1. Aether against Python, same model.** *Arms:* step 0; then per model: guided Aether; the no-guide fine-tune at two training seeds; Python with no guide; the base model in Python as the fine-tune's control. *Pool:* a part of B5's pool with Q29's oracle, drop rate reported; "neutral" is defined by script (no module files, JSON calls or contracts in the prompt) before tasks are written. *Measure:* first-attempt difference, and silent-wrong share on first attempt and after repair, over all attempts (KPI S). *Rule:* non-inferior, inferior or not resolved at Q29's margin, on a task-clustered bound. *Seed noise:* the same class at each training seed; repeats from B3's table. *Cost:* Q29; S per model per lane. *Needs:* B1, B4, B5.

**I2. What should a repair round carry?** *Hypothesis:* more detailed diagnostics improve repair (reported for a 14B open model on type errors in an agent loop, arXiv 2606.01522, which varied detail, not fix suggestions, and whose authors call the results preliminary). *First:* count the stored coded failures on the 1,026 tasks whose text would differ between arms (the test side); the 1,776's count is reported beside it as the drafting set. DG3 ships on the census (Q13); the count says only whether I2 is worth running, which it is if it resolves 5 points or less. *Arms:* resample; "failed, try again"; code and line; today's text, pinned to the pre-DG3 binary; the fix line, its table drafted from the 1,776's failures and tested on the 1,026's. After DG3 has shipped, I2 can change the table's entries, not the format. *Seed noise:* the seeds answer different programs, so the seed check has no form: same sign at each seed and a pooled interval over programs, beyond the A/A discordance. *Cost:* S per model. *Needs:* R1 scored, B1.

**I3. Does a fine-tune use a guide in its prompt?** *Hypothesis:* a null: two cards had no effect, the 1.5K-token card (`training/training_runs/qwen38-27b-modern/RESULTS.md:33,85-86`) and the 250-token fix-it card (`training/training_runs/qwen38-27b-r6/RESULTS.md:90-92`); neither was the medium guide. *Arms:* the published 12B and its unpublished second seed, medium guide against none, the no-guide cell twice, in one session on a part of the new pool; on the 1,026 tasks, which chose the published seed, only the second seed could decide. A truncated prompt stops the pass. *Rule:* a gain needs the lower bound above zero and the estimate above the A/A interval; otherwise the upper bound says what gain is ruled out, and Q27 closes if it is under Q27's margin. *Seed noise:* each contrast is within one set of weights; the sign must agree at both seeds. *Cost:* Q27; L. *Needs:* B2, B5.

**I4. Guide length and the small tier.** *Hypothesis:* length itself costs accuracy (reported on math, question answering and code generation, HumanEval included, for two open models of 7B and 8B and three hosted ones, arXiv 2510.05381). *Arms:* stage A in a 16K window: card with two repair rounds, card with six, small with two, so guide and repair budget separate. Stage B, window opened: medium against medium padded with inert text whose content, size and position the README fixes. *Rule:* D11's option (c) returns to the owner only if the bound on card-with-six minus small, after repair, is inside 3 points at no more tokens. *Seed noise:* no training seeds; repeats from B3's different-seed A/A. *Cost:* Q21; L per model. *Needs:* B3, B4, Q16, and B5's guided part under Q16(b).

**I5. Examples or prose: where should guide tokens go?** *Hypothesis:* example code carries most (reported for retrieved API documentation, arXiv 2503.15231). *Arms:* equal cuts, no rewriting: N tokens of examples; N of prose restating a rule; the current guide. N comes from B3's table, or the README says only a large effect resolves: the one measured 1,461-token cut read -2.3 [-9.1, +4.6] (`bench/results/small_ab_hostcut_20261026/README.md:10,97`). Two cut sets per category, drawn by seeded script from units the board's tasks exercise, must agree in sign. *Rule:* a cut order is stated only if the categories differ on Q16's instrument and the preferred arm is non-inferior at 3 points; more silent-wrong output is a loss. *Seed noise:* as I4. *Cost:* L. *Needs:* B3, B4, Q16, and B5's guided part under Q16(b).

**I6. The 32 GB consumer desktop.** *Why:* neither the 12B nor the MoE has run on such a machine (`training/training_runs/gemma4-12b-v2-q8/RESULTS.md:104`). *I6a:* step 5, on the 126 benchmark tasks. *I6b:* the MoE at mxfp4 (20.9 GB on disk; 26 to 29 GB resident on a larger machine, `training/training_runs/gemma4-12b-v2-4bit/README.md:37,78`; its repeat there, two days later with server versions not compared, changed 11 of 126 first attempts, the only repeat on record for that build and not a controlled A/A, `:57-59`) on that desktop, if I6a leaves the choice open. Both passes run on the desktop itself and wait on no other queue. *Rule:* "fits" by Q28's test, fixed before either pass; the repeat is the A/A for any score difference. *Seed noise:* one set of weights per model; the card says so. A product claim waits for I1. *Cost:* Q28; S per pass.

**I7. Do contracts turn silent wrong answers into stops?** *Arms:* on traps v2: Aether without contracts; with an enforced postcondition; with the same postcondition as a comment; Python with and without asserts. The contract author sees only the task prompt and is fixed before traps v2 is read. *Rule:* the claim is enforced minus comment, with false stops reported; resolution is computed from archived trap classes first; pass rate stays non-inferior at D37d's 3 points. The panel model is named beforehand on a base rate with room: one local board had 20 and 28 silent-wrong of 72 first attempts (`bench/results/b0_devstral_mlx4bit_20261011/README.md:49-50`). *Seed noise:* as I4, same sign in each half of the repeats. *Cost:* S per model. *Needs:* B7, DG2.

**I8. Format cost.** *Hypothesis:* none: the 12B reads 93 (106) of 126 at int8 against 97 (105) at 16 bits, but across different serving stacks (`training/training_runs/gemma4-12b-v2-4bit/README.md:35-36`). *Arms:* step 0; then every format in one session, with an int8 repeat as A/A and a 16-bit arm where the weights fit; the eight benchmark suites reported beside it; strata by prompt length. *Rule:* a cost is readable only if its interval excludes zero and its discordance exceeds the A/A's. *Seed noise:* one set of weights per model. *Cost:* L. *Needs:* B2.
